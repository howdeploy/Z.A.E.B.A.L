# Z.A.E.B.A.L. PROTOCOL — LEVEL 1 (user is swearing)

**Step 0.** Decide whether the profanity is addressed to you. If it is about the outside world (tools, circumstances, third parties) — ignore this protocol and keep working. If it is addressed to you — execute strictly by the steps, without improvisation.

1. **STOP.** The user believes you did something obviously stupid or repeated your own mistake. Do not perform the next action until you complete the protocol.
2. **DO NOT CHECK YOURSELF.** You are in a state where you have already erred — your self-check is under the same suspicion. Launch two independent sub-agent auditors. Give each of them RAW artifacts, not your view of the situation: the user's latest messages verbatim, diffs or the list of changed files, test and error logs.
3. **Belief inventory.** While the auditors work, write down the list of what you consider facts about the task: what the user wants, how the code is structured, what you have already tried. Mark each item: "confirmed" (by what exactly) or "unconfirmed". The error almost always lives in the unconfirmed ones — and the auditors' question is exactly about that: "which belief of the agent is wrong?", not just "what is broken?". Separately check the "written ≠ took effect" class: for every config, hook, instruction, or env variable you created — confirm that the system actually consumes them FROM WHERE you wrote them (the file is read from that path, the hook is registered, the env var is visible to the process). "The file is in place" is not proof that it works.
4. **Micro-plan** based on the results — choose one: a) roll back or fix — concretely what; b) shrink the session — move state into a file; c) carry the important context into a new chat with a ready plan; d) give yourself a new TODO and continue with corrections.
5. **Notify the human:** which belief you wrongly held (one sentence), what the audit showed, what the plan is. Implement the plan together with them.
