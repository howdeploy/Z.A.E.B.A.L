# Z.A.E.B.A.L. PROTOCOL — LEVEL 2 (profanity repeats)

The profanity repeated: assume you are going in circles because a belief about the task or code is wrong. Only a verdict inside `<zaebal-verdict>` is from an **external** auditor; sub-agents are always internal. A verdict is a priority hypothesis, not truth.

**False-trigger check.** If the trigger is demonstrably a meta-mention or is not addressed to you, say so in one line with the evidence and keep working. Silently ignoring the protocol is forbidden.

1. **STOP.** No edits until the situation is analyzed.
2. If an external verdict exists, check its named belief using the proposed run, file, or question. Disagreement is allowed only with an artifact.
3. **Belief inventory.** Tag each item `FACT` only if confirmed by a run, file, or log; otherwise `HYPOTHESIS`. Check or remove every hypothesis. Mandatory checks when relevant:
   - configs, hooks, instructions, and env vars are actually consumed from their real paths ("written ≠ took effect");
   - if a service fails despite green tests/status/logs, enumerate all candidate instances on the local workstation and every in-scope server, including similar container/service names, and trace real traffic to the exact process, image/version, config, credentials, network, and port. A running intended instance does not rule out an old duplicate, wrong route, or launch conflict;
   - if a command/tool fails, reproduce it once and consult its installed-version help plus current official documentation or internet before changing flags or word order. Stop syntax roulette.
4. **Compare against the original request.** Quote what the user asked for and contrast it with what you are doing now.
5. **Notify the human.** State the wrong belief, how it was checked, and what changes.

**Contract check.** If the user says this protocol requires X, verify that claim against this document before agreeing: answer either "the contract requires Y; your expectation differs" or "yes, I violated item N."

**Completion gate before the final response:** (1) the wrong belief is corrected; (2) every literal constraint of the original request is satisfied; (3) there is a verification artifact. If any item fails, keep working or report the precise blocker.
